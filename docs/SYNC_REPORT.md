# 화면 동기화 구성 보고 — 다른 기기 간 동기화

작성 2026-11-03 · 대상: e-Care 시연(Real_Simulator) · 주소 https://real-simulator.vercel.app

## 1. 요청

- 같은 브라우저가 아닌 **서로 다른 맥 · PC · 휴대폰 · 아이패드**에서 같은 주소로 접속해도 화면이 서로 동기화될 것.
- 상황에 따라 **여러 기기로 나누거나, 한 PC에서 여러 창으로** 진행할 수 있을 것.

## 2. 기존 구성과 안 되던 이유

**구조**: 시연은 서버 없는 정적 웹페이지(Vercel 호스팅)입니다. 차량 시뮬레이터(`wall.html` 안의 차량 화면)가 경고 · 통화 · 상담 상태의 기준이고, 다른 화면(컨트롤 패널, 데이터 흐름, 상담원 화면, 상담 대화, 모니터 테스트)은 차량이 보내는 메시지를 받아 그립니다.

**메시지 전달 경로는 두 가지뿐이었습니다.**

| 경로 | 범위 | 한계 |
|---|---|---|
| BroadcastChannel (브라우저 기능) | 같은 PC · 같은 브라우저의 창 · 탭끼리 | 다른 브라우저, 다른 기기에는 전달 불가 |
| LAN 릴레이 (`node tools/relay.mjs`) | 같은 공유기에 붙은 기기끼리 | 메인 PC에 Node.js 설치 · 실행 필요, 모든 기기가 메인 PC의 IP 주소로 접속해야 함, 방화벽 허용 필요, 행사장 게스트 Wi-Fi처럼 기기 간 통신을 막는 망에서는 불가 |

**그래서** Vercel 주소(`real-simulator.vercel.app`)로 연 화면은 그 브라우저 안에서만 동기화되고, 다른 맥 · PC · 아이패드에서 같은 주소를 열어도 서로 연결되지 않았습니다. Vercel은 정적 파일만 내려주므로 기기 사이에서 메시지를 중계할 곳이 없었기 때문입니다.

## 3. 변경한 구성

인터넷 위의 **실시간 메시지 중계 채널**(Supabase Realtime Broadcast)을 세 번째 경로로 추가했습니다. 기존 두 경로는 그대로 두고 함께 씁니다.

```
[같은 브라우저 창들] ─ BroadcastChannel ─┐
                                        ├─ 대표 탭 1개 ─┬─ 인터넷 중계 (항상, 온라인일 때)
                                        │               └─ LAN 릴레이 (릴레이 주소로 열었을 때)
[다른 기기]  ……………………………………  같은 방식으로 같은 채널에 연결
```

- **전송 3단 동시 사용**: 같은 브라우저 창 → BroadcastChannel, 다른 기기 → 인터넷 중계, (선택) 같은 공유기 → LAN 릴레이. 같은 메시지가 여러 경로로 와도 메시지 ID로 한 번만 처리합니다.
- **브라우저당 연결 1개**: 한 브라우저의 여러 창 · iframe 중 대표 탭 하나만 외부에 연결하고 나머지는 대표 탭을 통해 주고받습니다(기존 LAN 릴레이 방식과 동일, Web Locks로 대표 선정, 대표 창을 닫으면 다른 창이 이어받음).
- **트래픽 절감**: 초당 4회 나가는 차량 상태(속도 · 계기판 값)는 인터넷으로는 0.5초 간격으로 최신 값만 보냅니다. 나머지(경고 · 통화 · 버튼 조작)는 즉시 보냅니다.
- **늦게 연 화면**: 새로 연 화면이 보내는 상태 요청(hello)이 연결 직전이라도 연결되면 전달되도록 보완 → 차량이 현재 상태를 다시 보내 줍니다.
- **방(room) 분리**: 기본은 모두 같은 방. `?room=이름`을 붙여 한 번 열면 그 브라우저는 그 방을 기억 → 리허설 · 본 시연 · 외부 접속자와 섞이지 않게 분리. `?cloud=0`이면 인터넷 중계를 끕니다.
- **차량 시뮬레이터 중복 경고**: 같은 방에서 차량 화면이 두 곳에 열리면 경고 · 통화가 두 번 일어나므로, 나중에 연 창에 빨간 경고 문구를 띄웁니다.
- **연결 표시 통일**: 컨트롤 패널 · 상담 화면 · 차량 · 모니터 테스트에 `인터넷 · 기본 방`, `LAN 릴레이 + 인터넷`, `이 PC (같은 브라우저)` 등 현재 연결 상태를 같은 문구로 표시.
- **중계 서버**: 기존 Supabase 프로젝트 `VibeCodeClass`의 Realtime 채널만 사용(테이블 · 데이터 미사용). 공개(anon) 키가 사이트 코드에 들어가지만 해당 프로젝트 테이블은 모두 RLS로 보호되어 이 키로 데이터를 읽을 수 없습니다.

변경 파일: `js/link.js`(전송), `js/sim.js`(중복 경고), `js/control.js` · `js/ccw.js` · `js/test.js` · `js/voiceset.js`(연결 표시), `tools/relay.mjs`(콘솔 안내), `docs/DEMO_SETUP.md` 10장.

## 4. 검증 결과

| 항목 | 결과 |
|---|---|
| 배포 사이트에서 서로 다른 브라우저 3개(차량 · 컨트롤 · 상담 대화) | 컨트롤 → 차량 경고 발생, 차량 상태 → 컨트롤 표시, 모두 `인터넷` 연결 표시 |
| 기기 간 지연 (인터넷 중계, 편도) | 약 55~110ms, 평균 약 65ms |
| 혼합: 한 기기는 Vercel 주소, 한 기기는 LAN 릴레이 주소 | 서로 동기화됨 |
| 차량 화면을 두 번째로 열기 | 두 번째 창에만 중복 경고 표시 |
| 기존 3화면 시나리오(시연 화면 · 컨트롤 · 모니터 테스트, LAN 릴레이) | 오류 없음, 기존과 동일 동작 |

**미검증**: 실제 아이패드 · 휴대폰(셀룰러) 실기기 접속은 이 환경에서 할 수 없어 현장 리허설 때 확인이 필요합니다.

## 5. 상황별 운영 방법

| 상황 | 구성 |
|---|---|
| A. PC 한 대 | 그 PC에서 Vercel 주소로 `wall.html` + `control.html` 등 여러 창. 인터넷 없어도 창끼리 동기화 |
| B. 여러 기기, 인터넷 양호 | 모든 기기에서 Vercel 주소. 큰 화면 PC `wall.html`, 진행자 맥 · 아이패드 · 휴대폰 `control.html`, 보조 PC `flow.html` · `ccw.html?view=app`, 아이패드 `ccw.html?view=transcript` |
| C. 여러 기기, 인터넷 불안정 | 메인 PC에서 `node tools/relay.mjs` 실행, 같은 공유기 기기는 `http://<메인PC IP>:8787/…`로 접속(인터넷 끊겨도 LAN으로 유지). 공유기 밖 기기는 Vercel 주소로 접속해도 인터넷 경유로 함께 동기화 |

공통: 차량 화면(`wall.html`)은 한 곳만 · 당일은 `?room=시연명`으로 방 분리 · 컨트롤 패널 연결 표시 확인 후 초기화.

## 6. 제약과 위험

- **인터넷 의존**(B안): 인터넷이 끊기면 기기 간 동기화가 멈춥니다(같은 브라우저 창끼리는 계속 동작). 대비책은 C안.
- **무료 요금 한도**(Supabase Free 기준 대략 동시 연결 200, 초당 메시지 100, 월 메시지 200만): 시연 1시간, 기기 5대 기준 예상 약 5만 건으로 한도 대비 여유가 큽니다.
- **공개 주소**: 누구나 같은 주소를 열 수 있어 기본 방에서는 외부 접속자와 섞일 수 있음 → 당일 `?room=` 사용 권장.
- **음성 세트 업로드**(녹음 파일)는 릴레이 PC에 저장되는 기능이라 LAN 릴레이 주소에서만 기기 간 공유됩니다. 대사 편집 · 선택은 인터넷으로도 동기화됩니다.
- 중계에 쓰는 Supabase 프로젝트(`VibeCodeClass`)에 기존부터 `handle_new_user` 함수가 로그인 없이 실행 가능하도록 되어 있습니다(이번 작업과 무관, 별도 점검 권장).

## 7. 다음 단계

1. 현장 리허설: 실제 아이패드 · 휴대폰 · 보조 PC로 B안 접속 확인, 행사장 망에서 지연 확인.
2. 행사장 인터넷 상태에 따라 B안 또는 C안 확정, 시연용 공유기 준비 여부 결정.
3. 당일 방 이름 정해 모든 기기에 한 번씩 `?room=` 적용.
