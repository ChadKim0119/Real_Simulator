# e-Care Case A (긴급 · 주행불가) — 데이터 흐름 · 업무 흐름 명세

Real Simulator(`js/ecare.js`의 Director, `js/control.js`의 시나리오 1 · 전체 발표 1막)에서 실제로 돌아가는 흐름을 그대로 옮긴 것입니다. 다른 시뮬레이터(가상도시 등)에서 **같은 순서 · 같은 메시지 · 같은 상태값**으로 재현하는 기준으로 씁니다.

- 기준 경고: **엔진오일 압력 시스템** — WNG `OPW`, Case **A**, DTC `P0524`(Low Engine Oil Pressure)
- 고객: 홍길동 · 010-1234-5678 · 차량 GX 550
- 위치: 올림픽대로 한남대교 남단 부근
- 서비스센터: 강남 서비스센터 · 서비스 어드바이저 이정비
- 긴급출동: 마스터자동차

---

## 1. 등장 주체(노드)

| ID | 이름 | 역할 |
|---|---|---|
| `car` | 고객 차량(헤드유닛 HU · 계기판) | 경고 발생 · HU 팝업 · [전화연결] · 통화 |
| `phone` | 고객 휴대폰(Global App) | 앱 푸시 · 딜러 통화 |
| `vdp` | VDP | 차량 데이터 수집 · 차량/휴대폰으로 고객 문구 전달 |
| `vep` | TSP(VEP) | 필터 · Case 판정 · 고객 문구 매핑 · 각 시스템에 배포 · 상태 기록 |
| `ccw` | e-Care 고객지원실 CCW(상담원) | 긴급 케이스 응대 · 긴급출동 요청 · 상담 메모 · 서비스센터 이관 |
| `cti` | 콜센터 CTI | 아웃바운드 · 일반 전화(Case A 인바운드에는 쓰지 않음) |
| `dms` | 서비스센터 DMS(서비스 어드바이저) | 고객 컨택 · 예약 · 입고 · 정비 · 인도 · 종결 |
| `rescue` | 긴급출동(마스터자동차) | 출동 · 도착 · 견인 |

메시지 표기는 `보내는 곳 → 받는 곳 · API 이름 · 설명`이고, 패킷 이동 시간은 기본 **1.4초**(`TRAVEL = 1400ms`)입니다.

---

## 2. 상태값(케이스 하나에 붙는 값)

**상담 상태 `contact`**
`0 컨택 전` → `1 컨택 중`(상담원 통화 연결) → `2 상담 완료` → `3 이관 완료`(서비스센터로 이관)

**긴급출동 상태 `dispatch`** (−1 = 요청 전)
`0 신고접수` → `1 출동` → `2 도착` → `3 출동완료`

**서비스센터 상태 `dms`** (−1 = 이관 전, 코드는 DMS → TSP 전송값)

| 값 | 이름 | 코드 | 화면 라벨 |
|---|---|---|---|
| 0 | 컨택대기 | CONTACT_REQUIRED | — |
| 1 | 컨택 | CONTACTED | — |
| 2 | 예약 | RESERVED | 컨택 · 예약 확정 |
| 3 | 입고 | RECEIVED | 입고 |
| 4 | 정비 | REPAIR_STARTED | 정비 진행 |
| 5 | 정비완료 | REPAIR_DONE | 정비 완료 |
| 6 | 고객인도 | DELIVERED | 고객 인도 |
| 7 | 종결 | CLOSED | 정비 종결 · e-Care 과업 종료 |

**Case 등급**(WNG 판정 결과)

| Case | 라벨 | 의미 | 담당 | 첫 컨택 SLA |
|---|---|---|---|---|
| A | 긴급 | Malfunction · 주행불가 | e-Care 고객지원실 | 25분 |
| B | 경고 | Maintenance · 주행가능 · 점검 필요 | 서비스센터(DMS) | 1일 |
| C | 알림 | Notification · 정비 안내 | 서비스센터 · 고객 | 7일 |

## 3. 전체 흐름 한눈에

```
[1] 경고 발생   car → vdp → vep(필터 · Case A 판정) ─┬→ ccw  긴급 케이스 등록(인바운드 대기 25:00)
                                                    ├→ dms  경고 이벤트(첫 컨택 SLA 25분)
                                                    └→ vdp ─┬→ car    HU 팝업 “고객 지원실로 연결하시겠습니까?”
                                                            └→ phone  앱 푸시
[2] 고객 콜     car → ccw  헤드유닛 콜(HU [전화연결])
[3] 상담 통화   ccw → car  통화 연결 … 정차 · 비상등 · 긴급출동 동의
                ccw → rescue  긴급출동 요청
                ccw → car  통화 종료 · 후처리
[4] 이관        ccw → dms  상담 메모 이관                         (contact 3, dms 0 컨택대기)
[5] 출동 도착   rescue: 도착 → (12초) 시동 · 비상등 OFF → (20초) 출동완료
[6] 딜러 후속   dms → phone 딜러 발신 → phone → dms 통화 연결      (dms 1)
                예약 확정 → dms → vep DMS 상태(예약)               (dms 2)
[7] 견인 입고   rescue → dms 견인 입고(차량 이동) → dms → vep 입고   (dms 3)
[8] 정비        dms → vep 정비 진행(4) → 정비 완료(5)
[9] 인도 · 종결  dms → vep 고객 인도(6) → 종결(7) = e-Care 과업 종료
```

상담원(CCW)은 6~9단계의 서비스센터 진행을 **TSP 조회**로 확인합니다. 서비스센터가 상담원에게 직접 보내지 않고, 차량으로도 보내지 않습니다.

---

## 4. 단계별 상세

### 단계 0 · 준비 · 주행
- 초기화 → 시동 ON → 주행 시작. 이 단계에는 데이터 흐름이 없습니다.

### 단계 1 · 긴급 경고 → HU 팝업 (데이터 흐름)

| # | 흐름 | API | 설명 | 앞 단계 뒤 지연 |
|---|---|---|---|---|
| 1 | car → vdp | WNG · DTC | 경고 발생 · OPW + DTC P0524 | 0 |
| 2 | vdp → vep | VDP 이벤트 | WNG · DTC 이벤트 전달(VDP → TSP) | 0.7초 |
| 3 | vep 내부 | 필터 검사 | VIN · 정비 · 중복 필터 통과 | 0.5초 |
| 4 | vep 내부 | Case 판정 · 고객 문구 | OPW → 긴급(Case A) · 고객용 문구 매핑 | 0.5초 |
| 5a | vep → ccw | e-Care 이벤트 | CCW 긴급 케이스 등록 · 인바운드 대기 25:00 | 0.6초(5a~5c 동시) |
| 5b | vep → dms | DMS 이벤트 | 경고 이벤트 · 긴급 · 첫 컨택 SLA 25분 | 5a와 동시 |
| 5c | vep → vdp | 고객 알림 요청 | 고객 문구 → VDP · 차량 · 휴대폰 발송 요청 | 5a와 동시 |
| 6a | vdp → car | 헤드유닛 알림 | HU 경고 팝업 | 패킷 도착 후(1.4초) |
| 6b | vdp → phone | 앱 푸시 | 고객 앱 알림 · 엔진오일 압력 시스템 | 6a와 동시 |

- 고객 문구: “엔진오일 압력 시스템 경고가 감지되었습니다. 고객 지원실로 연결하시겠습니까?”
- 패킷이 **도착하는 순간** 각 화면이 반응합니다: CCW 케이스 목록, DMS 경고 이벤트, HU 팝업, 휴대폰 푸시.
- HU 팝업 내용: 아이콘 e-Care · 제목 ‘엔진오일 압력 시스템 이상’ · 안내문 4줄 · 버튼 [닫기] / [전화 연결]. 고객이 [닫기]를 누르기 전까지 계속 떠 있습니다.
- Case B · C라면 5a(CCW)는 없고 DMS로만 갑니다. HU 문구는 “지정된 서비스센터로 연결하시겠습니까?”입니다.

**주요 페이로드**

```
① car→vdp   { wngId:'OPW', counterValue:1, warningTriggerOccurrenceTime, latitude, longitude,
              odoInformationKm, vin, dtcInfo:[{ dtcCode:'P0524', system:'엔진 오일 압력',
              description:'Low Engine Oil Pressure', status:'CONFIRMED' }] }
② vdp→vep   { messageId, wngInfo:[①], dtcInfo:[…] }
③ 필터      { vinFilter:'pass', maintenanceFilter:'pass', duplicateFilter:'pass' }
④ 판정      { dataLabel:'OPW', warningName:'엔진오일 압력 시스템', case:'A',
              owner:'e-Care 고객지원실', customerMessage }
5a →ccw    { caseId, case:'A', vin, warning }
5b →dms    { vin, wngInfo:[{ wngId:'OPW', wngName, grade:'A' }], dtcInfo, thresholdMinutes:25 }
5c →vdp    { vin, customerMessage, targets:['헤드유닛','Global App'] }
6a →car    { popup: customerMessage, case:'A' }
6b →phone  { push: customerMessage }
```

### 단계 2 · 고객 HU [전화연결] → 고객지원실

| 흐름 | API | 설명 |
|---|---|---|
| car → ccw | 헤드유닛 콜 | HU [전화연결] → 고객지원실 · (대기 중인) 상담원 전화 수신 `{ from:'헤드유닛', vin, agent }` |

- CTI를 거치지 않고 상담원 화면에 바로 들어옵니다(전화 수신 팝업).
- 동시에 다른 통화가 진행 중이면 받지 않습니다(busy).

### 단계 3 · 상담원 전화 받기 · 통화 · 긴급출동

| 시점 | 흐름 | API | 설명 |
|---|---|---|---|
| 상담원 [확인] | ccw → car | 통화 연결 | 상담원 응답 · 헤드유닛 ↔ 상담원 통화(녹취) |
| 고객 긴급출동 동의 | ccw → rescue | 긴급출동 | 마스터자동차 출동 요청 · 현재 위치 `{ caseId, vin, location:'last received' }` |
| 통화 끝 | ccw → car | 통화 종료 | 통화 mm:ss · 후처리 |

- 상태: 상담원 ‘상담중’, `contact 1`. 긴급출동 요청 시 `dispatch 0`(신고접수), 4초 뒤 `dispatch 1`(출동 · 출동 기사가 고객에게 직접 연락 · 도착 예정 12분).
- 긴급출동은 상담원이 연결만 합니다. 출동사가 고객에게 직접 연락하고 현장을 처리하므로, 출동 이후 상태는 e-Care로 돌아오지 않고 차량으로도 가지 않습니다.

**통화 대본(16줄)과 대사에 묶인 동작**

| # | 화자 | 대사 요지 | 동작 |
|---|---|---|---|
| 1 | 상담원 | e-Care 고객지원실입니다. 홍길동 고객님 맞으실까요? | |
| 2 | 고객 | 경고등이 떠서 콜 버튼을 눌렀어요 | |
| 3 | 상담원 | 차분히 대처 요령을 안내해 드리겠습니다 | |
| 4 | 고객 | 어떻게 해야 하죠? | |
| 5 | 상담원 | 올림픽대로 한남대교 남단 부근 맞으신가요? 엔진 이상 경고 · 진단 정보 파악 | |
| 6 | 상담원 | 가까운 갓길에 세우시고 비상등을 켜 주세요 | **비상등 ON** |
| 7 | 고객 | 차량은 위험하지 않은 곳에 잘 세웠어요 | **차량 갓길 정차** |
| 8 | 상담원 | 긴급출동 접수 진행할까요? 강남 서비스센터 입고도 함께 도와 드릴까요? | |
| 9 | 고객 | 네네, 그렇게 해 주세요 | **긴급출동 요청(ccw → rescue)** |
| 10 | 상담원 | 서비스센터 연락, 이 번호로 드리면 될까요? | |
| 11 | 고객 | 네, 이 번호로 부탁드려요 | |
| 12 | 상담원 | 서비스센터에 전달하실 내용 있으실까요? | |
| 13 | 고객 | 아니요, 없어요 | |
| 14 | 상담원 | 곧 긴급출동 도착 · 출동 기사님 직접 연락 · 서비스센터도 빨리 연락드리도록 요청 | |
| 15 | 고객 | 빠르게 조치해 주셔서 감사합니다 | |
| 16 | 상담원 | 안전한 곳에서 기다려 주세요. e-Care 고객지원실이었습니다 | |

- 대사 간격: 각 대사 길이 + 0.7초. 마지막 대사 1.2초 뒤 긴급출동 요청을 다시 확인하고(이미 요청됐으면 생략), 2.6초 뒤 통화를 종료합니다.
- 진행자가 통화 중에 [다음]을 누르면 남은 대사를 즉시 기록하고, 대사에 묶인 정차 · 비상등 · 출동을 모두 적용한 뒤 통화를 종료합니다.

### 단계 4 · 상담 완료 · 서비스센터 이관(견인 전)

- 상담 메모가 자동으로 작성됩니다.
  - 상담 제목: 자동 입력
  - 통화 유형: 인바운드 콜
  - 메모: “엔진 오일 압력 경고(주행 불가) 발생. 위치 확인(올림픽대로 한남대교 남단 부근) · 갓길 정차 · 비상등 점등 확인. 긴급출동 요청 완료(출동 기사 고객 직접 연락 예정). 선호 서비스센터(강남 서비스센터) 진행 동의, 고객 연락처(010-1234-5678) 확인, 추가 전달 사항 없음.”
  - 요청 사항: “견인 입고 예정 차량입니다. 고객에게 빠른 연락 부탁드립니다.”
- 메모를 저장하고 ‘서비스센터 전달’을 켜면 이관합니다.

| 흐름 | API | 설명 |
|---|---|---|
| ccw → dms | 상담 메모 이관 | `{ title, callType:'인바운드 콜', centerName:'강남 서비스센터', memo, request, callSuccess:true }` |

- 상태: `contact 3`(이관 완료), `dms 0`(컨택대기). DMS 화면에 ‘컨택대기’로 뜨고 첫 컨택 SLA 타이머가 시작됩니다. 상담원은 ‘대기’로 돌아갑니다.
- 이관은 **견인차 도착 전**에 끝납니다. 출동 도착은 ‘긴급출동 요청 16초 이후 · 통화 종료 3초 이후 · 상담 메모 저장 이후’를 모두 만족할 때 자동으로 진행합니다(시연에서는 진행자가 ‘긴급출동 차량 도착’ 단계로 진행).

### 단계 5 · 긴급출동 차량 도착(현장)

- `dispatch 2`: 긴급출동 도착 · 고객 차량 앞 정차 · 견인 준비. 차량 화면에서는 견인차가 뒤에서 와서 운전석 옆을 지나 앞에 정차하는 장면이 나옵니다.
- 도착 **12초 뒤** 견인을 위해 차량 **시동 OFF · 비상등 OFF**.
- 도착 **20초 뒤** `dispatch 3`(출동완료 · 견인 후 서비스센터 이동).
- 이 단계에는 시스템 간 데이터 흐름이 없습니다.

### 단계 6 · 서비스센터(딜러) 후속 처리 · 고객 통화

| 시점 | 흐름 | API | 설명 | 상태 |
|---|---|---|---|---|
| 발신 | dms → phone | 딜러 발신 | 강남 서비스센터 이정비 어드바이저 → 고객 휴대폰 | |
| 3.2초 뒤 | phone → dms | 딜러 통화 연결 | 고객 응답 · 어드바이저 ↔ 고객 통화 | `dms 1` 컨택(컨택 이력 1차: 전화 · 컨택 · 예약대기) |
| 예약 확정 대사 | dms → vep | DMS 상태 | 컨택 · 예약 확정 · 내일 10:00 점검 · 오늘 견인 입고 | `dms 2` 예약 |
| 통화 끝 | dms 내부 | 딜러 통화 종료 | 통화 mm:ss · 오늘 견인 입고 · 내일 10:00 점검 예약 | |

**딜러 통화 대본(5줄)**
1. 딜러: 렉서스 강남 서비스센터 이정비 어드바이저입니다. 홍길동 고객님 되시죠? e-Care 상담센터에서 전달받고 연락드렸습니다.
2. 딜러: 많이 놀라셨죠. 견인 차량이 센터로 안전하게 옮기고 있으니 걱정하지 않으셔도 됩니다.
3. 딜러: 차량은 오늘 입고해 두고, 내일 오전 10시에 엔진 점검을 진행하려고 하는데 괜찮으실까요?
4. 고객: 네, 내일 10시 좋아요.
5. 딜러: 내일 오전 10시로 예약 확정해 드렸습니다. 점검 결과는 제가 직접 연락드리겠습니다. → **예약 확정**

- 예약 상태 페이로드: `{ vin, repairStatus:'RESERVED', repairStatusName:'예약', centerName, reservationAt:'(내일 10:00)', visit:'견인 입고 (오늘)', advisor:'이정비' }`
- 컨택 이력 1차는 ‘예약확정’ · ‘견인 입고(오늘) · 내일 10:00 엔진 점검 예약 확정’으로 갱신됩니다.
- 상담원(CCW)은 예약 정보를 TSP 조회로 확인합니다.

- 종결이 TSP에 기록되는 순간 모든 화면에 **‘e-Care 과업 종료’** 화면이 뜹니다.
  - 체크 링
  - 6단계 요약: 경고 감지 › 고객 연결 › 상담 · 긴급출동 › 서비스센터 이관 › 딜러 후속 통화 › 입고 · 정비 · 종결
  - 하단 문구: “강남 서비스센터 고객 인도 · 정비 종결 · 모든 상태가 TSP에 기록되었습니다”
- 전체 발표에서는 이어서 **‘다음 시뮬레이션 진행’** 단계가 옵니다. 과업 종료 화면은 유지되고, 아래에 ‘다음 시뮬레이션 진행 · 2막 상담원 아웃바운드’ 안내가 붙습니다. [다음]을 누르면 2막이 시작됩니다.

## 6. 분기(참고 · Case A의 다른 경로)

- **고객이 전화하지 않음**: 인바운드 대기 25:00 만료 → TSP 내부 ‘대기 만료’ → `vep → ccw 배정 대상`(유휴 상담원 · 경고 알림 팝업 · 응대 제한 05:00) → 상담원이 휴대폰으로 발신(`ccw → cti 발신 요청`, `cti → phone 발신`, 응답 시 `phone → cti 응답`). 이후는 3단계부터 같습니다(통화 종료는 `ccw → phone`).
- **발신 미응답**: `cti → ccw 미응답` → 재연결 대기 1분 → 재발신(최대 2회 재시도, 총 3회) → 3회 실패 시 `ccw → phone SMS` 자동 발송 → 메모에 ‘SMS 자동 발송, 고객 회신 시 즉시 출동 · 입고 안내 필요’ 기록 후 이관합니다.
