# Global South 시연 구성 가이드 (e-Care 멀티스크린)

시연 대상: 고객사 사장단 · 목표: 차량 경고 → 데이터 흐름 → 콜센터 → 출동 · 딜러까지 한 흐름으로, 여러 화면이 동시에 움직이는 장면.

## 1. 화면 구성 (최종 7면)

| # | 화면 | URL (릴레이 PC 기준) | 상태 |
|---|---|---|---|
| 1 | Instrument Cluster · 차량 시뮬레이터 + 컨트롤 패널 | `/` | 완료 |
| 2 | Head Unit (HU) | `/hu.html` | 다음 단계 (콜센터 · 딜러 연결) |
| 3 | Call Center Web (CCW) · 상담센터 사무실 | `/ccw.html` (CCW만: `/ccw.html?view=app`) | 완료 |
| 4 | 상담 대화 텍스트 | `/ccw.html?view=transcript` | 완료 |
| 5 | Data Flow Monitor | `/flow.html` | 예정 |
| 6 | Operation Web (OPW) · 설정값 조작 | `/opw.html` | 예정 |
| 7 | DMS · 딜러 시스템 | `/dms.html` | 예정 |

모든 화면은 같은 동기화 채널(`js/link.js`)을 씁니다. 차량 시뮬레이터가 시나리오의 기준(director)이고, 다른 화면은 상태를 받아 그리고 버튼 조작은 명령으로 되돌려 보냅니다.

## 2. 권장 방식: PC 1대(메인) + 필요 시 PC 1대(보조), 유선

**A안 (권장) — 고성능 PC 1대 + 다중 출력**
- 데스크톱 1대(RTX 4070급 GPU, DisplayPort/HDMI 4~6출력 또는 MST 허브), 각 TV에 브라우저 창을 하나씩 전체화면으로 띄움.
- 동기화는 같은 브라우저 안의 BroadcastChannel → **네트워크 없이** 0ms 수준으로 동기화. 무선 장애 · 방화벽 · 행사장 망 정책 영향이 없음.
- Chrome을 `--kiosk` 또는 창별 F11 전체화면, 각 창을 해당 모니터로 이동.

**B안 — 화면별 PC(또는 미니PC) + LAN 릴레이**
- 메인 PC에서 `node tools/relay.mjs` 실행 → `http://<메인PC IP>:8787/…`을 각 PC 브라우저에서 엶. 페이지가 릴레이를 자동 감지하여 LAN으로 동기화.
- 같은 서브넷, 유선 기가비트 스위치(8포트) 권장. 무선은 백업으로만.
- 포트 8787(TCP) 인바운드 허용, 모든 PC 같은 포트/주소 사용.

**C안 — 인터넷 공개 주소만 사용 (비권장)**
- Vercel 주소는 같은 브라우저 창끼리만 동기화. 여러 PC 간 동기화는 A/B안 필요.

| UPS | 1 | 메인 PC · 스위치 |

## 4. 시연 진행 (약 6분)

1. **시동** — 컨트롤 패널 `I` → "Welcome to Global South 개발 진척 보고회" 오프닝.
2. **주행** — `Space` 출발 → 커브 · 시가지 주행, 계기판 3D 시티 내비.
3. **긴급 경고** — `W` 브레이크 경고 → 계기판 경고등 · CCW에 긴급 케이스 접수(SLA 25:00 시작).
4. **25분 경과** — `T` → 인바운드 콜 없음 → 유휴 상담사 자동 배정 → CCW 경고 알림 팝업(05:00, 1분 미만 빨간색 · 알림음).
5. **전화 걸기** — CCW 팝업 [전화 걸기] 또는 `A` → e-Care 고객 응대 화면, 상태바 발신중 → 상담중 → 차량 갓길 정차 · 통화(녹음 음성) · 대화 화면 실시간 · 계기판 "e-Care 상담센터 통화 중".
6. **긴급출동** — 통화 중 자동 요청(또는 `E`) → 신고접수 → 출동 → 도착 → 출동완료, CCW 지도에 출동 차량 이동.
7. **상담 메모 · 이관** — 통화 종료 → 후처리중 → 상담정보 바텀시트(상담 메모 → 서비스센터 선택 → 상담내역 확인) → 저장 · DMS 전송 → 이관 완료(또는 `K`로 한 번에).
   - 변형 A: `G` 고객 전화(인바운드) → 전화 수신 안내 팝업 [확인] → 바로 상담.
   - 변형 B: `U` 고객 미응답 ON → 3회 발신 실패(재연결 대기 01:00은 `T`로 건너뛰기) → SMS 자동 발송 완료 → 상담 메모.
8. **초기화** — `R` (e-Care) · `X` (경고등) · `I` (시동 OFF → "See you soon").

## 5. 운영 팁

- 리허설 2회 이상, 시연 전 모든 화면을 한 번 클릭(브라우저 자동재생 정책으로 통화 음성 · 주변 소음이 막히지 않게).
- 콜센터 주변 소음은 상담원 화면 PC 스피커로만 나옵니다. 통화 음성이 잘 들려야 하는 구간에서는 `L`로 끌 수 있습니다.
- 절전 · 화면보호기 · OS 업데이트 · 알림 끄기, 브라우저 확장 프로그램 없는 전용 프로필.
- 오프라인 대비: 저장소를 메인 PC에 받아 `node tools/relay.mjs`로 로컬 실행(인터넷 불필요, 웹폰트만 기본 글꼴로 대체됨).
- 예비 PC에 같은 구성을 미리 띄워 두고, 장애 시 HDMI 스위처로 전환.

## 6. 아이패드(무선)로 상담 대화 화면 띄우기

1. 메인 PC에서 `node tools/relay.mjs` 실행 → 콘솔에 표시된 `transcript` 주소 확인 (예: `http://192.168.0.10:8787/ccw.html?view=transcript`).
2. 아이패드를 메인 PC와 **같은 Wi-Fi**에 연결 → 크롬에서 위 주소 열기. 우측 하단이 `● 차량 연결됨 · LAN`이면 동기화 중.
3. 메인 PC의 차량 · 상담원 화면도 **같은 릴레이 주소**(`http://192.168.0.10:8787/…`)로 열어야 합니다. `localhost`나 Vercel 주소로 연 창은 아이패드와 동기화되지 않습니다.
4. 처음 접속 시 iPadOS가 "Chrome이 로컬 네트워크의 기기를 찾으려고 합니다"를 물으면 **허용** (설정 → 개인정보 보호 및 보안 → 로컬 네트워크 → Chrome ON).
5. 화면을 한 번 탭하면 화면 꺼짐이 방지됩니다. 확실하게 하려면 설정 → 디스플레이 및 밝기 → 자동 잠금 → 안 함, 손님용으로는 손쉬운 사용 → 사용법 유도된 접근으로 크롬 고정.

안 될 때: 행사장 · 게스트 Wi-Fi는 기기 간 통신을 막는 경우가 많습니다(AP/클라이언트 격리). 시연용 공유기(또는 노트북 핫스폿)를 따로 두고, 메인 PC는 유선, 아이패드만 그 공유기의 Wi-Fi에 붙이세요. Windows는 처음 실행 시 방화벽 창에서 Node.js의 **개인 네트워크** 접근을 허용해야 합니다(포트 8787).

## 7. 대강당 3면 스테이지 (300인치급 × 3)

| 스크린 | 주소 | 내용 |
|---|---|---|
| 왼쪽 | `/stage.html?screen=left` | 고객 · 차량: 주행 중엔 운전석 · 계기판, 경고가 뜨면 헤드유닛(HU) 전체 + 계기판 PIP (리모컨에서 자동/계기판/HU 고정 가능) |
| 가운데 | `/stage.html?screen=center` | 데이터 흐름 모니터 (통화 중 음성 흐름 애니메이션, 상세 흐름은 접힘) |
| 오른쪽 | `/stage.html?screen=right` | 콜센터 사무실 · 상담원 화면 |
| 고객 HU (선택) | `/stage.html?screen=hu` | 고객 화면 2개 모드일 때 헤드유닛 전용 화면 |
| 진행자 | `/control.html` | 컨트롤 패널 (시나리오 · 자동 진행 · 멘트 · 수동 조작 · 고객 화면 1개/2개) |

- 송출 PC 1대(3출력)면 크롬 창 3개를 각 출력에 전체화면(`F`). 소리가 클릭 없이 나오도록 크롬을 `--autoplay-policy=no-user-gesture-required --kiosk` 옵션으로 실행하고, 창마다 `--new-window --user-data-dir`를 다르게 주면 편합니다.
- 모든 주소는 릴레이(`node tools/relay.mjs`) 기준. 컨트롤 패널 태블릿은 같은 네트워크에서 `/control.html`.
- 차량 시뮬레이터(시나리오 기준)는 왼쪽 스크린 안에서만 실행합니다. 같은 시점에 `index.html`을 다른 창으로 또 열지 마세요.
- 메인 시나리오: **1막 고객 인바운드** — 브레이크 경고 → HU 팝업 → 주행 중 고객이 HU [전화연결](실사 손이 화면을 눌러 줌, 시연 화면이 열려 있지 않으면 바로 눌림) → 상담원 화면 ‘전화가 왔습니다’ → 받기 → 통화(자막, 일레븐랩스 v4 녹음 9턴 · 통화 중 갓길 정차) · 긴급출동 → 완료 · 이관. **2막 상담원 아웃바운드** — 다시 경고, 고객 미연락 → 25분 경과 → 상담원 전화 걸기(고객 휴대전화 수신) → 완료 · 이관.
- 리허설: 한 모니터에서 `/stage.html?screen=all` + `/control.html`.
- 월요일 현장 확인 후 맞출 것: 화면 비율 · 입력 해상도, 3면이 분리형인지 연결형(엣지 블렌딩)인지, 음향 입력, 진행자 위치, 객석 거리(글자 크기).

## 8. 현장 모니터 테스트 (`/test.html`)

- 콘솔(`test.html`): ① 벽면 미리보기 — 현장 화면비로 3면 배치를 보고, 단계별 스틸(19장면 × 3면)을 넘겨 봄. 맞춤(레터박스)/채움(잘림), 화면당 1~2분할 구성. ② 현장 스크린 — 가운데/양쪽 화면비 · 가로 폭(m) → 세로 · 대각 인치, 맨 뒷줄 거리. ③ 출력 창 — Chrome “디스플레이 감지”로 맥이 인식한 디스플레이(해상도 · 비율) 목록, 화면마다 역할 창 열기, 톤 · 음성 테스트. ④ 연결 시나리오. ⑤ 체크리스트 · 메모 · 결과 복사.
- 출력 창(`test.html?out=1&role=left|center|right|all|sides`): 콘솔을 따라감. 키 F 전체화면, 1 패턴(원 · 안전영역 · 모서리 · 색 막대 · 신호 해상도 · 왼→오 스윕 바), 2 스틸, 3 가독성(맨 뒷줄 기준 글자 크기 판정), 4 라이브(실제 stage), 0 검정, ← → 장면.
- `all` = 한 소스를 장비가 3분할하는 경우, `sides` = C to 2HDMI처럼 양쪽이 같은 화면(미러)일 때.
- 스틸 다시 만들기: `node tools/relay.mjs &` 후 `NODE_PATH=$(npm root -g) node tools/capture-stills.cjs`.

- 한 브라우저(크롬 프로필) 안의 창 · 탭은 릴레이 연결을 하나만 씁니다(대표 탭이 나머지에 전달). 크롬의 호스트당 연결 6개 제한 때문에 3면 창을 한 PC에 띄우면 멈추던 문제를 막습니다.

## 9. 확정 구성: 디스플레이 한 대 (21:9 또는 16:9)

- 맥 → C to HDMI → 21:9 디스플레이. 외부 디스플레이 1대, 확장 모드. **해상도는 반드시 21:9(2560×1080 등)** — 16:9(1920×1080)로 나가면 디스플레이가 가로로 늘려 글자가 넓적해집니다(시연 화면이 경고 표시).
- 디스플레이: `wall.html` → 처음 화면에서 **21:9 / 16:9 모드** 선택(디스플레이 해상도에 맞는 쪽에 ‘이 화면에 맞음’) → 전체화면(`F`). 21:9 해상도를 고를 수 없는 16:9 모니터 · TV · 프로젝터는 16:9 모드.
- 진행: `control.html` (맥 화면 또는 태블릿 — 태블릿은 릴레이 주소로). ‘고객 차량 시선’은 기본 자동.
- 사전 점검: `test.html` → 디스플레이 감지 → 외부 디스플레이에 테스트 출력 → 패턴 · 스틸 · 가독성 확인 → 실측 폭 · 맨 뒷줄 입력.
- 배치 바꾸기: 시연 화면에서 `E` → 경계선 끌기(옆 패널이 함께 줄고, 권장 비율에서 초록 표시와 함께 멈춤) · 패널 끌어 자리 바꾸기 · `R` 기본 배치 → 다시 `E`. 이 브라우저에 저장되고 테스트 모드 미리보기에도 반영.

## 10. 여러 기기로 화면 늘리기 (맥 · PC · 휴대폰 · 아이패드 동기화)

**기본: 인터넷 주소 그대로** — 어느 기기든 `https://real-simulator.vercel.app/…`을 열면 인터넷으로 서로 동기화됩니다(Supabase Realtime 중계, 지연 약 0.1초). 설치 · 서버 · 같은 Wi-Fi 필요 없음. 기기 종류 · 브라우저가 달라도 됩니다.

| 기기 (예시) | 주소 `https://real-simulator.vercel.app/…` |
|---|---|
| 큰 디스플레이 PC | `wall.html` — 4분할 시연 화면 (차량 포함) |
| 진행자 맥 · 노트북 | `control.html` |
| 보조 PC · 추가 디스플레이 | `flow.html`(데이터 흐름) · `agent.html`(상담원 화면 CCW만) · `office.html`(고객지원실 실사, 컨트롤 패널 ‘상담실’ 시선을 따름) |
| 아이패드 | `control.html`(무선 진행) 또는 `ccw.html?view=transcript`(상담 대화) |
| 서비스센터 역할 PC · 태블릿 | `dms.html` (서비스센터 DMS 대시보드 · 컨택결과 등록이 CCW · 데이터 흐름에 반영) |
| 휴대폰 | `control.html`(리모컨) |

- 한 PC에서 여러 창으로 해도, 기기를 나눠도 똑같이 동작합니다. 섞어 써도 됩니다(일부는 한 PC의 여러 창, 일부는 다른 기기).
- **차량 시뮬레이터(`wall.html` 또는 `index.html`)는 같은 방 전체에서 한 곳만.** 두 번째로 열린 창에는 빨간 경고가 뜹니다 — 그 창을 닫으세요.
- 연결 표시: 컨트롤 패널 위쪽 · 상담 화면 오른쪽 아래 · 모니터 테스트 머리글에 `● 인터넷 · 기본 방`(또는 `LAN 릴레이 + 인터넷`)이 보이면 동기화 중입니다.
- **방(room)**: 기본은 모두 같은 방입니다. 리허설과 본 시연을 따로 돌리거나 다른 사람이 같은 주소를 열어도 섞이지 않게 하려면, 각 기기에서 한 번 `?room=이름`을 붙여 엽니다(예: `…/control.html?room=gs1105`). 그 브라우저는 이후 그 방을 기억합니다. 기본 방으로 돌아가기: `?room=main`.
- 인터넷 동기화 끄기: `?cloud=0`(그 브라우저에 기억), 다시 켜기 `?cloud=1`.

**인터넷이 불안정한 현장 — LAN 릴레이 함께 쓰기**
1. 메인 PC(맥)에 Node.js 18+ 설치, `git clone https://github.com/ChadKim0119/Real_Simulator.git` → `cd Real_Simulator`.
2. 시연 때 `node tools/relay.mjs` 실행 → 콘솔에 나온 `http://<메인PC IP>:8787/…` 주소를 같은 공유기의 기기에서 엽니다(처음 실행 시 방화벽 “수신 연결 허용”).
3. 릴레이 주소로 연 화면은 LAN과 인터넷을 **둘 다** 씁니다. 그래서 일부 기기는 릴레이 주소, 일부는 Vercel 주소로 열어도 서로 동기화되고, 인터넷이 끊겨도 같은 공유기 기기끼리는 계속 동기화됩니다.
4. 아이패드에서 릴레이 주소로 처음 접속할 때 “로컬 네트워크의 기기를 찾으려고 합니다”가 나오면 허용. 행사장 게스트 Wi-Fi는 기기 간 통신을 막는 경우가 많아 시연용 공유기를 따로 두는 것을 권장합니다.

**시연 직전 순서**: (릴레이를 쓰면 실행) → 차량이 있는 `wall.html`을 한 곳에서 열기 → 다른 기기 화면 열기 → 컨트롤 패널 연결 표시 확인 → 초기화.

참고: 녹음 음성 세트 업로드(상담 대화 › 대화 스크립트의 음성 세트)는 릴레이 PC에 저장되는 기능이라 릴레이 주소에서만 다른 기기와 공유됩니다. 대사 편집 · 선택은 인터넷으로도 동기화됩니다.
